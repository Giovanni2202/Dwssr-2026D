# Convención de Iconos para Commits
### Set de Iconos para Commits Convencionales

| Icono | Tipo de Commit | Cuándo debe utilizarse |
| :---: | :--- | :--- |
| ✨ | **`feat`** (Feature) | Cuando introduces una **nueva funcionalidad** o característica al proyecto (ej. añadir un nuevo formulario de contacto o una nueva ruta en Vue). |
| 🐛 | **`fix`** (Bug Fix) | Cuando **solucionas un error** o *bug* en el código existente. |
| ♻️ | **`refactor`** (Refactor) | Cuando realizas un cambio en el código que **no corrige un error ni añade una función**, sino que mejora la estructura interna (ej. optimizar una función de JavaScript o dividir un componente grande en unos más pequeños). |
| 💎 | **`style`** (Style) | Cuando haces cambios que **no afectan el significado del código** (espacios en blanco, formateo, falta de puntos y comas, comillas simples vs dobles). |
| 📚 | **`docs`** (Documentation) | Cuando creas o modificas **exclusivamente archivos de documentación** (ej. actualizar el archivo `README.md` o comentarios en el código). |
| ⚡️ | **`perf`** (Performance) | Cuando el cambio de código está enfocado puramente en **mejorar el rendimiento** (ej. optimizar consultas a la base de datos o reducir el tamaño de carga de imágenes). |
| 🚨 | **`test`** (Test) | Cuando **añades o corriges pruebas** automatizadas (tests unitarios o de integración) para asegurar que el código funciona. |
| 🔧 | **`chore`** (Chore) | Cuando realizas **tareas de mantenimiento** que no modifican el código fuente de la aplicación principal ni los tests (ej. actualizar dependencias en `package.json`, cambiar configuraciones de Netlify/Vercel o ajustar herramientas de compilación). |
